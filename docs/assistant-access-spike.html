Can an assistant read my expenses?

Research and the proposed shape for #79. Research only: no production code, nothing recorded in the decision log yet. Comment on any line you disagree with.

Ship the export pack (Shape A). Put the real effort into Siri and Apple Intelligence, not a server.

A ChatGPT side needs an OpenAI Platform organisation before a single expense can be read, and a hosted one is months plus a privacy promise we currently sell against. The Apple path needs no account, no endpoint and no change to the privacy policy, and it works with just the phone.

What changed since the issue was filed

Read 2026-11-09, 22:20 to 22:35 IST, from the vendor documentation itself. The issue was written on the assumption that ChatGPT connectors are remote-only and that a local server cannot be reached. Both halves have moved.

FactWhat it means hereSource
ChatGPT and Codex share one Plugins directory. A custom MCP server is added by URL with OAuth, no auth, or both. The connector path is a supported, documented feature, not a hack. plugins/quickstart, api/docs/guides/custom-mcp-server
Secure MCP Tunnel links a private stdio or HTTP server on the user's own machine to ChatGPT with no inbound port. It needs a Platform organisation, a tunnel id and a runtime API key. It cannot be distributed publicly. Shape B is cheaper than the issue assumed, and still out of reach for a phone-only user. api/docs/guides/secure-mcp-tunnels
Public distribution of an MCP-backed plugin needs a stable public HTTPS endpoint, verified identity, a ZIP and review. Shape C is a product and an operations job, not a feature. plugins/deploy/submission
Local stdio MCP plugins exist for the desktop, but local submissions are limited to approved partners, allowlisted. We cannot publish "TapLog reads your phone through your Mac" to anyone. plugins/deploy/desktop-only
Adding a custom MCP server happens on the web, and stays subject to workspace policy and Lockdown. The setup moment is a laptop and an admin, not the phone in a shop. custom-mcp-server
Apple: App Intents make an app's "content and actions discoverable by Apple Intelligence", and support Siri, Spotlight, Shortcuts and widgets. Foundation Models covers on-device and Private Cloud Compute models with structured output and tool calling. The same question, "what did I spend on food this month", is answerable with no account and no server. developer.apple.com, appintents and foundationmodels

The idea: Shape A, concretely

One new export next to the CSV. Same data rules, same free-export policy, a shape a model can read without a schema. It is a file the person shares, so nothing leaves the phone until they choose.

Then a prompt pack, six prompts written against that file, tried on real exported data:

Prompts worth shipping

  • Where did last month's money actually go?
  • Which category is closest to its budget?
  • What did I repeat most often, and what does it cost a year?
  • Find entries that look like duplicates.
  • What changed most against the month before, and why might that be?
  • If I cut one category by a fifth, what does the month look like?

Why this is not a throwaway

It answers the question people actually ask of spending data, with no account, and it tells us which questions are worth a server later. It also costs nothing to keep: the CSV exporter already owns quoting, archived and pending rules, and the temporary file lifecycle.

If Shape A is chosen, the same summariser becomes the payload a Shape B or C server would return, so the work is not lost either way.

The cheapest test of "is this a real request"

We have no user signal in either direction. Nothing in the repo measures it. So the first version counts, on the device only, how many people share the assistant summary against how many open the recap. A local counter, no network, no analytics service.
