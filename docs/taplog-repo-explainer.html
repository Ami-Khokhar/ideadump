TapLog — how everything works

Every component of the codebase, explained with diagrams and funnels. Built from a full read of Sources/ (72 Swift files, 4 targets), project.yml, the 23 test files, and the existing strategy docs. Branch budget-trees-redesign.

1The app in one funnel

TapLog is a local-first iPhone expense logger. The entire product is one loop: capture an expense in ≤5 seconds from anywhere, then pay the user back weekly with a recap, a streak, and a grove of budget trees that never die.

TapLog Pro — one paymentunlimited budget trees + the monthly recap

Everything above the Pro line is free and unlimited. Capture — the thing the app exists for — is never gated. The paywall appears only at the exact moment a user tries to plant a 4th tree or open the monthly recap.

2Project shape: one spec, four targets

project.yml (XcodeGen) is the single source of truth. Never hand-edit TapLog.xcodeproj — edit the YAML and run xcodegen generate.

Target map
App + widget + share extension all share one App Group (group.dev.amteshwar.taplog) holding the SwiftData store and the shared UserDefaults. All three carry the same MARKETING_VERSION/build number from one settings block. Shared source files (Models, Shared, math) are compiled into each target that needs them — that's why project.yml lists e.g. Shared/ under both extensions.

3App launch — what happens, in order

TapLogApp.init() runs five setup steps before the first frame; then ContentView decides what to show.

Cold-start sequence
Note the deliberate restraint: no network call, no analytics, no notification prompt, no App Store product fetch at launch. ProStore.start() reads entitlements locally and only listens — the price is fetched when the paywall appears, so a user without an Apple Account signed in never sees a sign-in dialog at launch.

4Capture: seven front doors, one form

Every entry point lands on the same capture surface (LogHomeView) or writes through the same persistence path. This is the app's core design rule: one capture form, infinite front doors.

Front doors → one pipe

Component-by-component (capture path)

Capture/LogHomeView.swift

Capture-first home

Hero amount display + custom in-app keypad (no system keyboard = no layout fight), 4 learned category tiles + More, 3-state impulse toggle (nil → impulse → planned → nil; unmarked is a real state), Log pill. Bottom-pinned so amount→Log is one thumb arc. Opening plant animation skipped for intent launches and Reduce Motion.

Shared/AmountInputFilter.swift

Amount input rules

Single tested filter for typed digits and pasted text: locale-aware separators (US 1,200 vs EU 12,50 vs Indian 1,20,000), 2-decimal cap, max ₹999,999,999.99, leading-zero trim. The keypad routes through the same filterEdit as the edit form.

Shared/Money.swift

Money

17 currencies, symbol + formatting from one place, human-separator parse (rightmost separator = decimal), Decimal end-to-end. fromAmount rounds intent Doubles to cents so 12.99 never becomes 12.9900000001.

Capture/EntryPersistence.swift

Visible refusals

Every save runs through one commit that rolls back on failure and shows a toast (“Couldn't save that expense — try again”). No silent data loss anywhere; undo failures explicitly report that nothing changed.

Shared/CaptureBookkeeping.swift

Shared bookkeeping

apply / revert run for every confirmed log regardless of door: category logCount+1 (drives tile ranking), lifetime log count, streaks/freezes via RetentionManager, widget timeline reload. Undo-safe with strict ordering.

Undo/UndoStack.swift

Undo toast

5-second toast, LIFO stack that survives toast expiry; budget-tree confirmation attached to log actions; failed-save reports enter the toast but not the undo history (nothing to reverse).

DeepLink/CapturePrefill.swift

Deep links

taplog://log?amount=¬e=&category=. Machine amounts are validated by a strict grammar distinct from human Money.parse — amount=12.345 pre-fills nothing rather than logging ₹12,345.

AppIntents/*

Siri & Shortcuts

Three intents: Log Expense (headless: Siri asks amount→category→optional note, saves, speaks confirmation), Open Expense Capture (Action Button/Control Center; writes a durable pending-activation that ContentView consumes → keypad focused, splash skipped), Quick Log (widget process, no UI). Category phrases use an AppEntity (“Log chai in TapLog”).

TapLogWidget/SpendWidget.swift

Widget

Small (today total + decorative tree), medium (today total + 3 learned quick-log buttons from real history via QuickButtonRanking — deterministic tie-breaks so taps can't drift), lock-screen circular/rectangular. 15-min refresh + reload after every log. Mis-tap undo: WidgetLogReceipt → app shows toast on next open (10-min window).

TapLogShare/ShareViewController.swift

Share sheet

Parses shared text for amount + merchant. OTP-gated: the loose bare-number fallback only runs if the text mentions spending (debit/spent/paid/₹…). Saves a pending entry (category Other); user confirms/discards in History. Fails with a message, never crashes the host app.

Shared/StoreLocator.swift

StoreLocator

Opens the SwiftData store once per process: prefers the App Group container, falls back to Application Support when the entitlement is missing (free-account dev builds), heals a split store by one-time row-by-row copy, and pins whatever opened so diagnostics never lie. The memoisation is load-bearing: Siri intents run in the app process — a second container would crash.

Shared/Log.swift

Logging

os.Logger with five categories; never logs amounts/notes; error descriptions redacted to domain+code so a sysdiagnose can be shared safely.

5Budgets & the grove — the signature mechanic

The moat-feature: each budgeted category is a tree whose state encodes two periods of history, not just one number.

Tree health = f(current period, previous period)
A tree never dies — chronic overspend is “resting”, by design the app does not punish. Changing target or cadence stamps budgetHealthResetDate so a new target can't retroactively re-judge an old period (fairness). Cadence conversion preserves real rates (₹50/wk → ₹216.67/mo, honest 52÷12). Everything is Decimal, calendar-injectable, and unit-tested.
Budget/GroveStripModel · GroveSceneModel · GroveScene

Rendering pipeline

GroveStripModel.tree(for:) derives state → strip on capture screen (cap + overflow count) → full grove on Budgets (deterministic FNV-1a hash per category → species, x-position, depth, bloom — same layout every launch).

Budget/TreeMark · TreeStateGlyph · TreeSpeciesArt

Three tree renderers

Hand-authored vector marks on a 64×80 canvas (six states, ~950 lines of path data, crown depth from compositing translucent leaf copies); a badge-size silhouette glyph for tiles/widget; species art for the grove. All Canvas-based, tinted, VoiceOver-labelled.

Budget/BudgetSetupView · BudgetTargetEditor · BudgetsView

Budget UI

Plant/edit budgets with live tree preview, stepper grid (weekly ±50 / monthly ±250), cadence switch converts the target honestly. Budgets screen lists spent-vs-target per period with last-period comparison.

Capture/GroveStrip.swift

GroveStrip on capture

Small strip above the keypad; trees at a glance before the tap; over-budget trees tinted clay. Kept quiet so the amount stays the hero.

6Recap, streaks, and the one notification

Retention loop
Recap/RecapMath.swift

Recap math (pure, tested)

Locale-correct week splitting (Sunday-first safe), daily bars, category shares, month-week blocks. Impulse vs planned is computed over marked spend only, with an explicit coverage disclosure — a partial answer is never presented as complete.

Recap/WeeklyRecapView.swift

Recap screen

Weekly span free; monthly span is the Pro moment. Totals vs previous, daily bars, category breakdown, budgets section, impulse read, CSV export (free, always).

Retention/RecapNotifier.swift

The one notification

“Your week is ready. / See where it went.” — no amounts on the lock screen. Permission requested only after the recap was opened or a week completed (the prompt can only be spent once). One request ID → rescheduling is idempotent; tapping routes to Recap.

Shared/RetentionManager.swift

Streaks

Weekly target (3–7 days), streak in weeks, freezes earned per 10 logs (max 3) absorb a missed week; week start from the user's calendar; cross-process flock so a widget log and the app can't corrupt the mask; undo never takes earned streaks away.

7The Pro layer

Paywall decision flow
The paywall appears at two moments only — never at launch, never on a timer. Evidence-based: below 8 entries / 3 days it shows the grove illustration instead of thin numbers. On unlock it dismisses itself; purchase cancellation is silence, not an error dialog. CSV export is deliberately free forever — it's the only way data leaves the device, and charging for it turns the privacy pitch into a hostage situation.

A log from Siri/widget/deep link on first launch counts and skips the whole flow — the app never replays setup screens at someone who already did the thing. Killed mid-onboarding resumes at the stored step. Every gate is a small, tested predicate in OnboardingFlow (pure functions over UserDefaults).

9Data model, privacy, themes

Models/Entry.swift

Entry

amount (Decimal) · category key · note · date · isArchived · isPending · intent: SpendIntent? (nil = unmarked, deliberately a third state) · createdAt. Optional intent survives lightweight migration honestly: old rows land “unmarked”, never fabricated.

Models/SpendCategory.swift

SpendCategory

key (stable slug) / name / emoji / sortOrder / logCount / budgetTarget+period+resetDate. Entries reference categories by key — renaming or deleting never breaks history (falls back to “Other”). 13 India-friendly defaults seeded once.

Theme/*

Design system

Paper #F7F5F2 / ink #121110 / sage #6B8F71 accent, serif display numerals (monospaced digits), PaperGround texture, VineBorder, organic surfaces, seed-growth opening. Motion policy respects Reduce Motion everywhere; every decorative Canvas has an accessibility label.

Settings/SettingsView.swift

Settings

Currency (17, shared with extensions via App Group defaults), appearance override, weekly log target, faster-ways guide, Pro + Restore, delete-all (resets streaks, cancels the recap notification, zeroes category learning). Warns visibly when the App Group isn't available (widget/share blind).

Export/CSVExporter.swift

CSV export

RFC 4180 quoting, formula-injection neutralization (=+-@ prefixed with '), pending entries excluded, archived included, intent spelled “unmarked” rather than blank. ShareLink-based, free forever.

Privacy posture

No account No server No analytics No tracking No third-party deps Zero networking symbols. The only data that leaves the device is what the user shares themselves (CSV, support email).

11Tests & quality gates

23 test files cover every pure-logic subsystem: money parsing (all separator cultures), amount filter, budget math (tree states, cadence conversion), recap math (locale week pinning), streaks (freezes, undo, week rollover), share parser (OTP rejection), store fallback + healing, widget receipts, paywall evidence, Pro gate, onboarding predicates, intent validation, CSV quoting, undo stack, persistence refusals.

Strength

The "pure enum + injectable calendar" architecture is why 300+ assertions exist without a UI test rig.

Watch

No CI: tests are hand-run, and the generated .xcodeproj is committed beside project.yml — classic drift pair. One GitHub Actions job would lock it in.

Gap

UI layer is untested by design; nothing has had a hands-on device pass since the keypad redesign (see Aug 28 review §8).
